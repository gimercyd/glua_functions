<div align="center">
  <h2>Прочее</h2>
  <h3>Custom timer</h3>
</div>

<div>
  <pre><code>
function createTimer(delay, callback)
    local start = CurTime()
    return function()
        if CurTime() >= start + delay then
            callback()
            return true
        end
        return false
    end
end
  </code></pre>
  <p1><b>Памятка</b> Эта функция недостаточно раскрывает возможности <code>CurTime()</code>, вы можете взять эту функцию за основу и улучшить/обезопасить. Не советую использовать <code>timer.Create</code>, так как при лагах сервера могут возникнуть сбои, также сильно нагружают сам сервер при большом количестве. Также <code>CurTime()</code> отлично работает с хуком <code>Think</code>, который обрабатывает каждый тик сервера.</p1>
</div>

<div align="center">
  <h3>Выдача эффектов</h3>
  <p1><i>! Важное упоминание в случае, если вы хотите сделать сложную систему с использованием разных эффектов типо скорости, регенерации или ХП.</i> Важно понимать, что все базовые эффекты (например, скорость) хранятся в формате таблицы. Если вы просто запишите изначальную скорость игрока в переменную через <code>ply:GetWalkSpeed()</code>, а затем выдадим новую скорость через <code>ply:SetWalkSpeed()</code> - это будет <b>небезопасная</b> выдача в том случае, если вы выдаете эффекты из нескольких источников. Glua аддоны и файлы обрабатываются в алфавитном порядке, и если вы в двух разных аддонах выполните вышеупомянутые действия, то последний аддон запомнит скорость последнего баффа, а не изначальной скорости игрока, потому что в памяти вы сохраняете последнее значение скорости игрока. </p1>
  
  <p1>! Для оптимальной системы вам надо создать отдельную библиотеку сервера, где будет ваш кастомный геттер и сеттер скорости с уникальным id модификатора. Таким образом вы сможете выдавать игроку сумму всех эфффектов, сохраняя только его изначальную скорость и сумму всех баффов.</p1>
  <p1>Базовая библиотека эффектов - <a href="https://github.com/gimercyd/glua_functions">SimpleEffectsLib</a> <i>[разработка]</i></p1>
</div>

<div align="center">
  <h3> umsg warning </h3>
  <p1>Если вы сталкиваетесь с таким варном: <code>Warning: [number] global queued usermessages!</code>, то в таком случае:</p1>

  <p1>Вы используете аддон/gm, который использует устаревший метод umsg. Сервер будет ложиться с одинаковой периодичностью при высокой нагрузке (<30 игроков) вне зависимости от мощности хоста. Вам надо проанализировать все свои аддоны на вызов функции <code>umsg.Start</code></p1>
  
  <p1>Однако, зачастую проблема более очевидна и вероятнее всего хранится в ядре DarkRP, потому что в данный момент никто не использует библиотеку umsg, предпочитая net. Обычно именно <code>_notify</code> перегружает буфер, поэтому мы удалим именно его.</p1>
  
  <p1>Перейдите в <code>gamemodes/darkrp/gamemode/modules/base/sv_util.lua</code>, затем удалите следующие функции в файле: <code>DarkRP.notify</code>, <code>DarkRP.notifyAll</code>

  <p1><b>Важно!</b> Если фикс не решил вашу проблему - перебирайте каждый umsg вызов и смотрите, какой именно флудит в буфер.</p1>
